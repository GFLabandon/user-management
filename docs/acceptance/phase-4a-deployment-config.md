## 最终 JAR 的隔离 MySQL 验收

采用本机 Java 17.0.20、独立 MySQL 9.0.1，数据库只监听 `127.0.0.1:13318`，应用只监听 `127.0.0.1:18089`。应用使用仅获授权访问临时测试库的 `counselor_app`，不是 root。

| 场景 | 结果 |
| --- | --- |
| 启动脚本缺少 DB_URL、混入 demo、配置 root | 非零退出且含 DEPLOY_CONFIG；未出现 Hikari 初始化，错误未回显测试密码 |
| 配置正确但空账号库没有首次凭据 | 非零退出；V4 表结构可建立，账号表仍为空 |
| 正确首次凭据 | 建立唯一管理员，数据库存储 bcrypt 哈希；登录成功，页面不出现 demo 密码 |
| 实际表单登录 | 从登录页读取 CSRF token 后提交成功，跳转档案页 |
| 移除首次凭据后重启 | 原密码可登录；账号数量、密码哈希及版本保持不变 |
| 上传目录探测 | 验收结束没有遗留探测文件 |
| 日志核对 | 应用日志未包含本次随机数据库密码或管理员密码 |

配置变更先完成一轮隔离验收；Security 修复后使用最终 JAR 再跑同样流程。测试结束关闭应用和 MySQL，删除专属临时数据库目录和凭据文件，未操作现有数据库。
