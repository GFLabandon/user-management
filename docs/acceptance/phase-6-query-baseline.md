# 第 6 阶段：查询性能基线

日期：2026-10-02。基线提交 `0e2546e`，分支 `codex/query-baseline`。本轮完成可重复测量，**保留现有业务 SQL 和索引**；没有新增迁移、缓存或修改备份格式。此处是本机单客户端查询基线，不是网页端到端延迟、容量测试或生产性能承诺。

## 测量方法

`docker/QueryBaseline.java` 从打包应用加载实际 `CounselorMapper`、`AuditMapper` 和 Service 查询方法，使用 MyBatis 生成绑定 SQL，不另抄一套查询。直接创建 Service 对象，数据库连接手动设为 REPEATABLE READ；不包含 Spring 代理、连接池获取、HTTP、安全过滤器、模板渲染或事务回滚耗时。数据库连接固定复用，每次采样后回滚读事务；禁用跨语句一级缓存，每次都执行真实 SQL。

使用随机新建的私有 Compose 项目，拒绝非空数据库，运行原始 Flyway V1–V4。构造 100／1,000／10,000 份档案，对应 1,000／10,000／100,000 条操作记录。数据完全合成：10 个院系、50 个操作者、60 天日期分布，任职状态及操作结果按固定模数生成，包含相关性，不能代表真实学校的分布。

每档包含 11 个场景：档案首页、末页、院系加状态、子串检索、无结果；操作记录首页、末页、操作者、日期加结果、对象编号、无结果。每场景预热 3 次，再采样 30 次；p95 采用排序后的第 29 个值，另保存中位数、最小／最大值及全部样本。执行计划在计时之外通过同一 Mapper 的 BoundSql 执行 `EXPLAIN ANALYZE` 取得，绑定值来自合成数据。

每一次查询都对照 Java 生成的预期总数和有序 ID 列表校验分页结果，同时统计 JDBC statement prepare 次数：档案查询为 **2 条 SQL**；操作记录为 **3 条 SQL**，第三条查询页面显示的数据库会话时区。计划查询、建数与正确性断言不计入查询计时。全部 33 个场景通过。

## 结论与后续触发条件

- 院系＋状态查询使用现有 `idx_counselors_department_status`，大档 p95 约 0.50 ms；目前没有增加同类索引的依据。
- 子串查询的计数会扫描档案表；大档无匹配时两个查询均需扫描，p95 约 6.05 ms。保留现有“包含”语义，不为索引改变成前缀匹配。
- 审计操作者、对象筛选及部分日期组合计数出现全表扫描。大档无匹配操作者的计数和列表均扫描 10 万行，p95 约 55.44 ms；对象筛选 p95 约 32.51 ms。这是后续优先观察的路径，不能据此宣称查询已经优化。
- 深分页成本随偏移增大：大档档案末页 p95 约 14.82 ms，审计末页约 23.55 ms。执行计划证实需要读取或排序更多行；当前保留页码式交互。

当前样本下耗时没有出现秒级延迟，但尚无实际使用负载或响应时间目标，不能据此证明满足生产需求。本轮先保留结构，避免为了增加索引扩展 V5 和备份兼容范围。若真实数据量、访问频率或完整请求 p95 不满足明确目标，再围绕审计对象／操作者筛选做候选索引对照；同时验证大小写语义、返回正确性、写入成本、空间以及迁移恢复。没有对照实验时不写提升百分比。

## 复现与收尾

```sh
docker build --target query-verification -t campus-counselor-queries:local .
python3 -B scripts/benchmark-queries.py
```

脚本不接受已有项目／数据库地址，只生成随机 `counselor-baseline-*` 环境；需已有 Docker 和 Compose，凭据仅在私有临时文件内。结果保存在 `target/query-baseline/<随机项目>/result.json`，结束后删除本次容器、网络和卷。强制杀进程或 Docker 异常时，应按报告中的精确项目名核查遗留资源，不使用全局删除卷的命令。

本次项目 `counselor-baseline-dcf71f7691d0` 的报告记录 `resourcesCleaned=true`。随后检查时 Docker 守护进程已不可用，因此没有再次启动 Docker 仅为重复核查。工具镜像构建运行 111 项 Java 测试，0 失败／错误／跳过；29 项 Python 安全测试通过，文档链接与差异检查通过。33 场景本身另做真实 MySQL 结果、分页和 SQL 数量断言，不计入 Java 单元测试数量。

第 6 阶段不改变应用运行代码；5B 的 13 组运行、5 组迁移、10 组恢复证据见[5B 验收](phase-5b-image-cleanup.md)。新镜像阶段只用于测量，不进入默认 Web 运行镜像。远程 CI 与安全门禁以候选 PR 为准，基线已有的 MySQL 镜像发布阻断仍需独立处理。
