# 4C：协调备份与空环境恢复验收

验收日期：2026-09-25。分支：`codex/backup-recovery`，基线为 4B 的 `493fed6`。本阶段新增维护脚本、恢复演练、Python 安全测试与操作文档，没有修改 Java、V1–V4、应用依赖或 Compose 运行配置。尚未合入 main 或推送远程。

## 交付与约束

- `scripts/backup.sh` / `restore.sh`：调用 Python 3.9+ 标准库实现；显式指定项目与权限受限的环境文件。
- `scripts/maintenance.py`：核对源应用实际连接、独占卷和数据库状态，停止应用并持有数据库读锁，协调导出 SQL 与头像；记录镜像 ID、全部表数据摘要、迁移历史和图片清单。
- 恢复前检查私有副本、完整性及文件路径；目标必须是全新项目，镜像与数据库版本须匹配。导入后检查数据内容及图片摘要，应用保持停止，操作者再启动并验证页面。
- 保留合法孤立图片，不清理业务文件；不覆盖现有数据库或卷，不自动重新启动源应用，不把失败恢复目标自动删除。
- `.github/workflows/ci.yml` 增加 Python 安全测试步骤。没有推送，本次未运行远程 CI，真实 MySQL CI 留待 4D。

操作命令及故障处理见[备份恢复指南](../guides/backup-and-restore.md)。

## 未涵盖的范围

仅支持现有单实例 Compose、独占命名卷和 V1–V4 表结构。没有验收跨架构／跨数据库版本恢复，也不支持外部共享数据库、额外业务表、存储过程或多操作者同时维护。

备份文件限制访问，但脚本未实现加密、签名、定时备份和异地保管。校验值用于发现损坏，不能认证来源；仅恢复可信备份。没有生产数据、真实用户规模、零丢失、自动切流或固定恢复目标的证据。
